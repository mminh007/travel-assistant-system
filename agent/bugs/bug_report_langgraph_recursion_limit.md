## 1. Executive Summary

When a user submitted a request to plan a 3-day 2-night tour in Da Lat, the system executed the query through a complex multi-agent cognitive architecture (`Planner` -> `ReAct Executor` -> `Finding Extractor` -> `Fact Checker` -> `Evaluator` -> `Task Manager`).

The workflow failed at **step 25** with error `gRPC Internal / GRAPH_RECURSION_LIMIT`:
```text
Runtime exception: Recursion limit of 25 reached without hitting a stop condition. 
You can increase the limit by setting the `recursion_limit` config key.
For troubleshooting, visit: https://docs.langchain.com/oss/python/langgraph/errors/GRAPH_RECURSION_LIMIT
```

Simultaneously, the execution logs revealed **three other severe issues regarding model quality and evaluation findings (LLM Evaluation Findings)**:
1. **Fact Checker Failure:** Output token length overflow (`Could not parse response content as the length limit was reached`).
2. **Language Drift & Geographic Hallucination:** The Vietnamese query triggered Chinese output (`三天两夜Dalat之旅包括岘港接机...`) alongside a major geographic hallucination (arranging airport pickup in Da Nang — 岘港 — for a Da Lat tour, ~700 km apart).
3. **Ineffective Reflection/Rework Loop:** `evaluator_agent` repeatedly rated output as `DEFICIENT`, triggering two consecutive, unproductive rework cycles that exhausted graph execution step budget.

## 2. Identified Bugs & Failure Analysis

### Bug 1: LangGraph Recursion Limit Reached (`GRAPH_RECURSION_LIMIT`)
* **Log:**
  ```text
  [2026-10-29 02:56:42] [ERROR] [ChatStreamService] Runtime exception: Recursion limit of 25 reached without hitting a stop condition.
  [2026-10-29 02:56:42] [ERROR] [GrpcServerCore] ==> [gRPC] Error from ChatStreamService: Recursion limit of 25 reached without hitting a stop condition.
  ```
* **Code Location:** [agent/app/services/streaming/chat_stream_service.py](../app/services/streaming/chat_stream_service.py#L88-L137)
* **Root Cause:** The `trace_config` passed into `graph_instance.astream_events(...)` **omits the `recursion_limit` parameter**, causing LangGraph to enforce its default cap of **25**. However, the Planner broke the request into **4 tasks**, each requiring ReAct loops, tool executions, fact validation, and evaluator reflections. The total steps required for this workflow range from 50 to 80 steps.

---

### Bug 2: Fact Checker Token Length Overflow (`Length Limit Reached`)
* **Log:**
  ```text
  [2026-10-29 02:56:18] [ERROR] [CognitiveNodes] ❌ [FACT CHECK FAILURE] Skipping validation. Trace: Could not parse response content as the length limit was reached
  ```
* **Root Cause:**
  - The `fact_checker` node relies on Structured Output (`FactCheckResult`).
  - The itinerary generated by the executor was excessively verbose, causing prompt input + generation tokens to exceed the `max_tokens` threshold configured on the LLM Factory for this node.
  - The LLM cut off before completing the required JSON schema, causing the LangChain / Pydantic JSON parser to crash and bypass the verification step entirely.

---

### Bug 3: Language Drift & Geographic Hallucination
* **Log:**
  ```text
  [2026-10-29 02:56:21] [INFO] [CognitiveNodes] ==> [PROCESS] FINDING_EXTRACTOR Extracting structured findings from executor output...
  [INFO SUMMARY] [CognitiveNodes] Extracted 1 finding(s). Summary: '三天两夜Dalat之旅包括岘港接机、城市景点游览、Datanla瀑布等景点，最后返回岘港。...'
  [2026-10-29 02:56:23] [WARNING] [CognitiveNodes] ⚠️ [FACT CHECK] Contradictions detected: ['The executor claim mentions ']
  ```
* **Analysis:**
  - **Language Drift:** The user query was in **Vietnamese**, but during Rework Cycle 1, `Qwen/Qwen2.5-3B-Instruct-AWQ` switched entirely to **Chinese** in its summary and output.
  - **Severe Geographic Hallucination:** The model formulated a Da Lat itinerary that scheduled: *"airport pickup at Da Nang airport (岘港接机) ... visit Datanla falls ... and return to Da Nang"*. Da Nang and Da Lat are located nearly 700 km apart with no direct ground commute feasible for a short tour.
  - While `fact_checker` flagged contradictions, it lacked autonomous remediation capabilities and simply forwarded the state to the Evaluator.

---

### Bug 4: Ineffective Evaluator Rejection & Uncontrolled Rework Loop
* **Log:**
  ```text
  [2026-10-29 02:56:19] Status: ❌ DEFICIENT | Scores: Tools=4, Evidence=3, Citations=2, Freshness=1 | Correction Required: True | Rework Cycle: 1
  [2026-10-29 02:56:24] Status: ❌ DEFICIENT | Scores: Tools=2, Evidence=2, Citations=1, Freshness=1 | Correction Required: True | Rework Cycle: 2
  ```
* **Analysis:**
  - The 3B model lacks the reasoning capacity to adhere to strict corrective directives issued by `evaluator_agent` ("Generate detailed itinerary with specific accommodations, citations, freshness...").
  - After the first rework cycle, evaluation scores actually **regressed** (Tools dropped from 4 to 2, Evidence dropped from 3 to 2).
  - These two rework iterations consumed **12 steps** exclusively on Task 1, draining nearly half the total step budget.

## 5. Remediation Plan & Recommended Fixes

### Recommendation 1: Increase `recursion_limit` in Code
Update [agent/app/services/streaming/chat_stream_service.py](../app/services/streaming/chat_stream_service.py):
```python
trace_config = {
    "recursion_limit": 100,  # Increase to 80-100 to support 4 subtasks + reflection cycles
    "metadata": {
        "session_id": session_id, 
        "user_id": user_id,
        "source": source
    },
    "configurable": {
        "thread_id": f"{user_id}_{session_id}"
    }
}
```

### Recommendation 2: Implement Strict Language Locking in System Prompts
Inject an explicit constraint into system prompts for `travel_react_agent`, `finding_extractor`, and `evaluator_agent`:
> *"CRITICAL: Always generate responses in the exact language used in the initial user query (Vietnamese). Never switch to Chinese or any other language unless explicitly requested by the user."*

### Recommendation 3: Optimize `fact_checker` Node
* Increase `max_tokens` for structured generation on the `fact_checker` LLM Factory instance.
* Truncate or pre-summarize verbose executor outputs before passing them into the verification schema to prevent context limit crashes.

### Recommendation 4: Constrain Evaluator Rework Cycles
* Cap maximum rework cycles to **1** instead of 2 per subtask. If evaluation fails after 1 retry, proceed with the best available output rather than exhausting the graph budget.

### Recommendation 5: Upgrade / Tier the LLM Strategy
* The `Qwen2.5-3B` parameter size is insufficient for high-level multi-agent reasoning, critique, and self-correction.
* **Suggested Tiering:**
  - Retain `3B` only for lightweight routing / guardrails (`input_guardrail`).
  - Upgrade core cognitive nodes (`planner`, `travel_react_agent`, `evaluator_agent`) to **`Qwen/Qwen2.5-7B-Instruct`** (AWQ/GPTQ) or higher, depending on VRAM headroom.
